# Evidence — phase-2-control-loop

## What changed

Control is tenant-scoped: unauthenticated dashboards redirect to login, a Demo Co session cannot see Northwind workloads, ingest without a bearer is 401, and a Demo Co token cannot write Northwind's orgId. Alerts POST to a webhook. A `block` budget refuses the follow-up event (`accepted: 0`, `budget_block`). Northwind starts with zero events, receives `calibrated` fleet priors, then `measured` after `ingest:live`. Docker compose is in `deploy/`.

## How it was measured

Same Control port 3002, same repo-root SQLite `file:/workspace/ark.db`, HTTP + SQL.

- Unauthenticated `GET /dashboard` and `GET /login`
- `POST /api/v1/events` with no Authorization, with a mismatched orgId, with a Northwind token
- `GET /api/v1/calibration` as Northwind before and after `npm run ingest:live`
- SQL `COUNT(*)` of Northwind events
- Two POSTs to `wl_northwind_blocked` against a $0.0001 `block` budget
- Webhook sink on `127.0.0.1:9876` plus `alert_deliveries`
- Form login as dana and sam, HTML of `/dashboard`

Capture timestamps and commit SHAs are in `captures.tsv`.

## What this does not prove

No real customer's production traces — Northwind's 40 traces were generated by `ingest:live` in this container. Docker Compose was not executed here (no Docker daemon); the file is present and the entrypoint is written. Webhook delivery was to a local sink, not Slack's hosted API. Session cookies are HMAC-signed, not encrypted. Public internet hosting was not completed: this environment has no AWS/Vercel/Railway token and no tunnel binary.

## Deviations

`GET /api/v1/calibration` no longer honours `?org=` as tenancy. Org comes from bearer or session. `fetchCalibration` sends `ARK_CONTROL_TOKEN` when set. The old open ingest path remains only when `org_tokens` is empty (pre-seed).

No new third-party runtime dependency.

## Definition of done

- **Cost / latency impact:** Alert delivery is bounded (`timeoutMs` 3s) and does not fail ingest. Session verify is HMAC, no DB on each cookie check beyond login. Ingest adds one budget-spend query per distinct workload in a batch.
- **Observability for new failure modes:** Failed deliveries land in `alert_deliveries` (`ok=0`, `error`). Budget block/throttle appear as `circuitBreaks.reason`. Login failures redirect with `?error=1` rather than a stack trace.
- **Docs or ADR updated:** README demo accounts and `ingest:live`. `docs/05-hosting.md`. Roadmap Phase 2 records what shipped vs what still needs a real customer. Architecture notes that `?org=` is not a tenancy control.
